## 一、产品与角色域

| 术语 | 定义 |
|------|------|
| 智能问诊系统 | 本产品正式名称，提供健康咨询问答与体检报告分析两大 AI 服务的 Web 应用，版本 v1.0。 |
| 健康信息助手 | 系统的产品定位：帮助用户初步了解症状、读懂体检报告、明确就医时机的信息辅助工具。 |
| 普通用户 | 系统唯一角色，进行健康咨询、上传体检报告、查看结果与历史记录的人。本期无医生、管理员角色。 |
| 非诊断边界 | 系统的合规红线：不提供疾病诊断结论、不推荐具体处方药、不替代专业医疗服务。 |
| 免责声明 | 声明 AI 输出仅供参考的文字。系统级固定文案为"智能问诊系统 v1.0 \| 仅供健康咨询使用，不替代专业医疗建议"，另每次 AI 回复末尾与分析报告均附内容级免责提示。 |
| 敏感健康数据 | 体检报告内容、咨询对话等个人健康信息，适用隐私保护规则（R-BR-09）。 |
| Spec Coding | 本项目的工程方法：需求 → 原型 → 设计 → 开发 → 测试 → 运行，每阶段有文档化交付物。 |

## 二、健康咨询域

| 术语 | 定义 |
|------|------|
| 健康咨询 | 模块一：用户以自然语言描述症状或健康疑问，AI 流式返回结构化解答的功能。 |
| 多轮上下文 | 同一会话内，请求 AI 时携带本会话历史消息使回答保持连贯的机制；超长时自动截断（默认保留最近 20 条）。 |
| 会话 | 一段连续咨询对话的单位，对应数据库 `conversation` 表；含标题（首问前 30 字摘要）与多条消息。 |
| 消息 | 会话中用户或 AI 的一条发言，对应 `message` 表，含 role（user/assistant）与 Markdown 原文。 |
| 流式输出 | AI 回复逐段增量返回并展示的机制，技术上为 SSE 协议；前端呈"打字机效果"。 |
| 打字机效果 | 流式输出在前端的视觉表现：文字逐字/逐段出现。 |
| Markdown 渲染 | 将 AI 回复中的标题、加粗、列表、表格、emoji 等标记语法渲染为排版样式的过程；要求流式过程中不出现半截标签。 |
| 五段式结构 | 健康咨询 AI 回答的强制输出格式：症状分析、缓解建议、需警惕事项、何时就医、温馨提示，缺一不可（FR-12/C-BR-04）。 |
| 症状分析 | 五段式第①段：对症状的简明解析与可能原因说明，标注"非诊断"。 |
| 缓解建议 | 五段式第②段：可操作、无风险的护理与生活建议。 |
| 需警惕事项 | 五段式第③段：明确列出的"不建议做"的危险行为。 |
| 何时就医 | 五段式第④段：分级就医时机，须含时间阈值或伴随症状条件。 |
| 温馨提示 | 五段式第⑤段：免责声明，强调仅供参考、以医生诊断为准。 |
| 急危重症 | 胸痛、呼吸困难、大出血、意识障碍等危及生命的症状场景；AI 必须优先且醒目提示"立即拨打急救电话或就近就医"（C-BR-07/C-E7）。 |
| 欢迎引导 | 进入页面或清空会话后展示的 AI 助手能力说明与免责提示。 |
| 清空对话 | 重置当前会话的操作：二次确认后清空消息区并恢复欢迎引导，上下文同步重置（C-BR-06）。 |
| 防重复提交 | AI 回复进行中禁用发送按钮，阻止并发请求导致上下文错乱（C-BR-08/C-E8）。 |
| 无关/违规输入引导 | 对与医疗健康无关或含违规内容的输入，AI 说明定位并引导回归健康咨询主题（C-E6）。 |
| 报告追问 | 针对某次体检分析结果继续提问的场景，会话携带该报告的分析摘要作为上下文（US-303），会话 `scene=report_followup`。 |

## 三、体检报告域

| 术语 | 定义 |
|------|------|
| 体检报告 | 用户提交的反映体检结果的文件，本系统仅接受文本型 PDF 格式。 |
| 文本型 PDF | 含可选择文字层的 PDF，能被解析库直接提取文字，是本期支持的唯一可分析类型。 |
| 扫描件 PDF | 由图片构成、无文字层的 PDF；本期不解析，触发"无法识别"提示，OCR 识别列为二期扩展。 |
| OCR | 光学字符识别，将图片/扫描件中的文字识别为可处理文本的技术。 |
| 上传区 | 报告分析页中承载点击、"选择文件"按钮、拖拽三种上传方式的界面区域；拖拽悬停时高亮。 |
| 拖拽上传 | 将文件拖动释放到上传区完成上传的交互方式。 |
| 三重校验 | 文件类型（仅 PDF）、文件大小（≤10MB）、空文件（0 字节拦截）三项校验的合称；前端即时执行 + 后端兜底，错误文案一致。 |
| 双重判断 | 文件类型校验同时检查扩展名与 MIME 类型，防止改后缀绕过。 |
| 10MB 边界值 | 大小限制的验收口径：≤10485760 字节允许上传，+1 字节拒绝。 |
| 异步受理 | 报告分析的处理模式：上传校验后立即返回 `report_id`，解析在后台执行，前端轮询结果；避免长连接阻塞。 |
| 轮询 | 前端按固定间隔（2s）查询分析状态直至终态（success/failed）或超时（120s）的取结果方式。 |
| 文本提取 | 从 PDF 中抽出纯文本的过程；提取结果为空或 <50 字判定为"无法识别"。 |
| 四段式结构 | 报告分析结果的强制格式：基本信息、异常项明细、总体健康建议、注意事项，缺一不可（R-BR-05）。 |
| 基本信息 | 四段式第①部分：报告日期、体检机构、姓名、性别、年龄等，未识别字段可为空。 |
| 异常项明细 | 四段式第②部分：逐条列出异常指标，每条须含检测值、参考范围、异常状态、改进方案四要素（R-BR-06），不得只给结论。 |
| 检测值 | 某项指标的实际测量结果（如"145 mmHg"）。 |
| 参考范围 | 该指标的正常值区间（如"90–140 mmHg"），异常状态的判定基准。 |
| 异常状态 | 指标相对参考范围的偏离方向：`high` 偏高 / `low` 偏低，界面以 ⚠️ 标记 + 颜色区分。 |
| 改进方案 | 针对单个异常指标的可执行改善建议（生活方式、复查、就诊科室等）。 |
| 总体健康建议 | 四段式第③部分：跨指标的汇总性健康改善方向。 |
| 注意事项 | 四段式第④部分：需特别留意的风险项与就医提醒，含内容级免责声明。 |
| 急危指标 | 严重偏离的异常指标（如肿瘤标志物显著升高）；触发醒目"建议尽快就医"警示且不截断分析（R-BR-10/R-E9），对应数据字段 `has_critical`/`critical`。 |
| 阅后即焚 | 隐私处理策略：上传的原始 PDF 仅供本次解析，解析完成（无论成败）立即从服务器删除，不落盘留存（数据库设计第 3.3 节）。 |
| 脱敏 | 敏感信息入库前的遮蔽处理：如姓名保留首字其余以 * 代替。 |
| 重新分析 | 清空当前结果回到上传初始态，更换报告再次走完整流程的操作（= 再次调用上传接口）。 |
| 下载报告 | 将四段式分析结果导出为 txt 文件（UTF-8 带 BOM）供用户保存的操作。 |

## 四、历史记录域

| 术语 | 定义 |
|------|------|
| 咨询历史 | 按会话聚合的历史咨询记录列表（标题+时间倒序），支持回看与删除（FR-8）。 |
| 分析历史 | 体检报告分析记录的列表（文件名、分析时间、总体评估摘要），仅含成功记录，支持回看与删除（FR-9）；失败记录不进列表（US-304）。 |
| 删除记录 | 物理删除历史数据且不可恢复的操作，调用前必须二次确认（FR-14）。 |
| 历史记录回看 | 打开历史条目查看完整对话或完整四段式报告的功能。 |
| 历史条目 | 列表中的单个历史记录对象。 |
| 报告分析记录 | 对应数据库 `report_analysis` 表的一行：一次上传分析的全量结果。 |
| 归属标识 | 记录属于谁的依据：**V2.0 起唯一口径为 user_id**（登录用户），所有业务查询/删除 WHERE 必带；V1.0 的 client_id 已废弃。 |

## 五、技术契约域

| 术语 | 定义 |
|------|------|
| client_id | 前端 localStorage 持久化的 UUID，V1.0 无登录体系下的数据归属依据（请求头 `X-Client-Id`）。**V2.0 已彻底废弃**：数据库删除该列、接口不再接受该请求头，历史测试数据随库重建清零。 |
| 4301（已退役） | V1.0 "客户端标识非法"错误码；V2.0 起从错误码表退役，同类场景（凭证缺失/失效）统一由 4411 承载。 |
| DeepSeek | 本系统调用的大语言模型服务（纯文本模型，OpenAI 兼容接口），负责咨询回答与报告分析；不能直接读取 PDF，故报告须先文本提取。 |
| API Key | 调用 DeepSeek 的鉴权密钥，仅存后端环境变量（`DEEPSEEK_API_KEY`），禁止进入前端、代码仓库与数据库。 |
| SSE | Server-Sent Events，服务器向浏览器单向推送的 HTTP 流式协议，本系统 `/api/chat` 采用（事件：start/token/done/error）。 |
| 统一响应格式 | 所有 JSON 接口的响应结构 `{code, message, data}`；业务错误也返回 HTTP 200，由 code 区分。 |
| 业务错误码 | 1.3 错误码表中定义的 4xxx/5xxx 编码，message 即用户可见中文文案。 |
| 降级 | 依赖服务异常时的保底行为：友好提示 + 允许重试 + 不丢会话/不残留半成品（C-BR-09/R-BR-07）。 |
| 僵尸记录 | 后台异常导致长期停留在 processing 状态的受理记录，由后端定期清理。 |
| 结构化输出契约 | DeepSeek 分析报告的返回必须匹配 abnormal_items 等 JSON Schema，缺字段视为解析失败；同时是接口 7 响应与数据库 JSON 列的共同标准。 |
| 越权校验 | 用 A 的凭证访问/删除 B 的数据必须失败的安全规则（V2.0 按 user_id 过滤）。 |
| 越权统一口径 | 越权访问他人记录的响应与"记录不存在"完全一致（4302"记录不存在或已被删除"），不区分两种情况，避免向攻击者泄露记录存在性（历史记录需求异常表、US-605）。 |
| 冒烟测试 | 阶段 5/6 通过 `GET /api/health` 验证服务存活的最基础用例。 |

## 六、用户认证域（V1.1 新增，V2.0 扩充）

| 术语 | 定义 |
|------|------|
| 用户账号 | 系统在 `user` 表中登记的注册主体，由用户名（3-20 位字母/数字/下划线，唯一）、邮箱（格式合法且唯一）、密码（6-20 位）三要素构成。 |
| 双唯一性 | 注册时用户名与邮箱都必须全系统唯一的约束；由 `uk_username`/`uk_email` 唯一索引兜底并发注册，冲突提示"用户名已存在"/"邮箱已被注册"。 |
| 加盐哈希存储 | 密码保存方式：随机盐 + 单向哈希后入库，格式 `pbkdf2_sha256$迭代数$盐(hex)$哈希(hex)`（Python 标准库 hashlib.pbkdf2_hmac 实现），存于 `user.password_hash`；数据库、接口、日志任何环节都不出现明文（对应 4405 校验链）。 |
| auth_token 表 | 登录凭证持久化表（V2.0 新增，数据库设计 3.2）：Token 主键 + user_id 外键 + expires_at（颁发 +7 天）。价值：服务重启不掉登录态、登出=删行、可按用户级联清理；过期行由后端定期清理。 |
| 密码二次确认 | 注册表单要求重复输入密码并比对，不一致提示"密码不一致，请重新输入"且前端不发起提交（4406 为后端兜底码）。 |
| 登录态（Token） | 登录成功后服务端颁发的不透明随机串（`secrets.token_hex(32)`，64 字符），服务端以 auth_token 表行为载体，前端保存（localStorage）；有效期内刷新页面不丢登录态、服务重启依然有效。 |
| X-Token | V2.0 起业务接口的身份请求头（注册 A1、登录 A2、健康检查除外）：服务端按头值查 auth_token 且未过期 → 解出 user_id 注入业务查询；缺失/过期返回 4411"登录已过期，请重新登录"。 |
| 统一失败文案（防枚举） | 登录失败无论因账号不存在还是密码错误，一律提示"用户名或密码错误"（4410），避免攻击者借此枚举系统内的用户名。 |
| 跳转链路 | 注册成功 → 登录页；登录成功 → 主页面；退出/登录态失效 → 登录页。三处跳转是认证模块的固定导航规则。 |
| 需登录资源 | 历史记录页与历史类接口（咨询会话/分析记录的列表、回看、删除）：未登录访问跳转登录页，操作强制 user_id 归属校验，越权统一按"记录不存在"（4302）处理。 |
