# 用户登录功能 — 需求描述

| 文档版本 | V1.0 |
|----------|------|
| 编写日期 | 2026-10-18 |
| 关联文档 | 《用户注册功能需求.md》《历史记录查看功能需求.md》 |
| 页面形态 | 独立页面 `login.html`；登录成功进入主页面 `index.html` |

## 一、核心规则

1. 输入**用户名 + 密码**，两者与注册信息匹配成功 → 返回登录成功，**跳转到主页面**。
2. 登录页提供"去注册"入口，点击跳转注册页。
3. 登录成功后维持登录态（服务端会话或 token），主页面与历史记录等功能据此识别当前用户；登录态过期需重新登录。
4. 主页面显示当前登录用户，并提供"退出登录"（退出后回到登录页）。

## 二、异常场景

| 场景 | 提示文案 |
|------|----------|
| 用户名为空 | "请输入用户名" |
| 密码为空 | "请输入密码" |
| 用户名或密码错误（含账号不存在、密码不匹配两种情况） | 统一提示 **"用户名或密码错误"** |

> 安全约定：失败提示不区分"账号不存在"还是"密码错误"，防止他人枚举系统内的用户名。

## 三、补充约定（简要）

- 密码校验基于注册时的哈希值比对，任何环节不落明文。
- 登录接口失败不返回密码相关字段；前端密码输入框为密文显示。

## 四、验收要点

1. 用已注册账号正确登录 → 跳转主页面，且主页面可见登录用户与历史记录入口。
2. 密码错误 → 提示"用户名或密码错误"，停留在登录页；不泄露账号是否存在。
3. 用户名或密码留空提交 → 提示"不能为空"，不发起请求。
4. 未登录状态直接访问主页面功能数据/历史记录 → 跳转回登录页。
5. 退出登录后，再访问历史记录 → 要求重新登录。
