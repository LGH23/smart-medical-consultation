|----------|------|

> 本需求引入登录体系，正式关闭 PRD 待确认项"是否需要用户注册/登录"（关闭为：**需要**）。

## 一、核心规则

1. **用户名**：3~20 个字符，只能包含字母、数字、下划线；全系统唯一。
2. **密码**：6~20 个字符。
3. **确认密码**：6~20 个字符，必须与密码输入一致。
4. **邮箱**：符合标准邮箱格式；全系统唯一。
5. 注册成功后**跳转到登录页面**。
6. 注册页提供"去登录"入口，点击跳转登录页（与登录页的"去注册"互跳）。

## 二、异常场景

| 场景 | 提示文案 |
|------|----------|
| 用户名已存在 | "用户名已存在" |
| 邮箱已被注册 | "邮箱已被注册" |
| 两次密码输入不一致 | "密码不一致，请重新输入" |
| 用户名格式不正确（长度超限或含非法字符） | 具体提示，如"用户名需为 3-20 位字母、数字或下划线" |
| 密码长度不合规 | "密码需为 6-20 个字符" |
| 邮箱格式不正确 | "邮箱格式不正确，请重新输入" |

## 三、补充约定（简要）

- 密码**加密存储**（哈希加盐），数据库严禁存明文；接口与日志中也不得出现明文密码。
- 格式校验**前端即时提示 + 后端二次校验**，两侧文案一致（沿用 PRD 错误提示总则）。
- 唯一性以数据库约束为准（用户名、邮箱建唯一索引），并发注册冲突返回对应"已存在"提示。

## 四、验收要点

1. 用合法数据（如 `user_01 / Abc123 / 同密码 / a@b.com`）注册成功，页面跳转到登录页。
2. 重复用户名注册 → 提示"用户名已存在"；重复邮箱 → 提示"邮箱已被注册"。
3. 两次密码不同 → 提示"密码不一致，请重新输入"，且不提交注册。
4. 非法用户名（`用 户名!`、2 字符、21 字符）→ 给出具体格式错误提示。
5. 绕过前端直调注册接口，后端仍执行同样校验并返回相同文案。
