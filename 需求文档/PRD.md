## 1. 产品概述

### 1.1 项目背景

普通人面对身体不适时缺乏医学知识，难以判断是否需要就医；拿到体检报告后，也常被专业术语和指标缩写困扰。本产品借助 DeepSeek 大模型的医学知识理解与语言表达能力，为普通用户提供**健康咨询问答**与**体检报告智能分析**两大核心服务。

### 1.2 产品定位与边界

- 定位为**健康信息助手**：帮助用户初步了解症状、读懂体检报告、明确就医时机。
- **不是互联网医院**：不提供疾病诊断结论、不推荐具体处方药、不替代专业医疗服务。
- 全程强调"仅供参考、及时就医"的免责边界，急危重症优先引导就医。

### 1.3 用户角色

| 角色 | 说明 |
|------|------|
| 普通用户 | 唯一角色，持有系统账号（用户名+密码+邮箱注册）。进行健康咨询、上传体检报告、查看分析结果与历史记录。 |

> 本期不含医生端、管理端。**V1.1 引入注册登录体系**：注册成功跳登录页，登录成功进入主页面；历史记录仅登录用户可见本人数据。

## 3. 模块一：健康咨询（FR-1、FR-2、FR-12）

### 3.1 详细描述

**对话问答**
- 用户在输入框输入健康问题（如"牙疼怎么办"），点击发送按钮或按 Enter 提交；Shift+Enter 换行。
- 输入框展示占位引导文案；发送成功后输入框清空。
- 系统调用 DeepSeek 生成回答，以**流式输出**（打字机效果）逐段展示，首字响应 ≤5s。
- 回答支持 **Markdown 渲染**：标题、加粗、列表、表格、emoji；流式过程中不得出现标签错乱或半截结构。
- AI 回复过程中禁用发送按钮（置灰 + loading），防止重复提交。

**会话管理**
- 欢迎引导：进入页面或清空会话后，展示 AI 助手能力说明与免责提示。
- 清空对话：点击"清空"按钮先二次确认，确认后重置会话并回到欢迎语状态，上下文同步重置不残留。
- 上下文连贯：同一会话内保留多轮上下文，AI 结合历史对话作答；上下文过长自动截断（保留最近 N 轮）。

**AI 输出要求（五段式，缺一不可）**

| 部分 | 内容要求 | 示例 |
|---|---|---|
| 症状分析 | 简明解析症状，说明可能原因（非诊断） | "牙痛可能由龋齿、牙龈炎或智齿引起" |
| 缓解建议 | 可操作、无风险的护理/生活建议 | "冷敷面颊、避免刺激性食物" |
| 需警惕事项 | 明确列出"不建议做"的危险行为 | "不要自行服用抗生素、不要用偏方止疼" |
| 何时就医 | 分级就医时机，含时间阈值与伴随症状 | "持续 1–2 天未缓解应就诊；伴发热应尽快就医" |
| 温馨提示 | 免责声明，强调仅供参考 | "以上建议仅供参考，请以专业医生诊断为准" |

输出约束：语言通俗、分点清晰；不给明确诊断结论、不推荐具体处方药；急危重症（胸痛、呼吸困难、大出血、意识障碍等）**优先且醒目**提示"立即拨打急救电话或就近就医"；无关/违规输入引导回归健康咨询主题。

### 3.2 业务规则

| 编号 | 规则 | 说明 |
|---|---|---|
| C-BR-01 | 输入校验 | 空内容（纯空格）不允许发送，提示并聚焦输入框 |
| C-BR-02 | 长度限制 | 单次输入最大 2000 字符，超长提示或截断 |
| C-BR-03 | 流式渲染 | 必须流式返回并正确解析 Markdown，避免标签错乱 |
| C-BR-04 | 结构完整性 | 回答须含五段式结构，缺失视为异常 |
| C-BR-05 | 免责强制 | 任何回答均附就医建议与免责声明 |
| C-BR-06 | 会话隔离 | 清空对话后上下文同步重置 |
| C-BR-07 | 医疗边界 | 急危重症优先提示"立即就医" |
| C-BR-08 | 防重复提交 | AI 回复进行中禁用发送 |
| C-BR-09 | 故障降级 | 网络异常/超时/服务错误时友好提示，不中断会话，允许重试 |

### 3.3 异常场景

| 场景 | 触发条件 | 预期处理 |
|---|---|---|
| C-E1 空输入 | 发送空串/纯空格 | 拒绝发送，提示并聚焦输入框 |
| C-E2 超长输入 | 超过长度上限 | 限制输入或截断并提示 |
| C-E3 请求失败 | 网络异常/服务 5xx | 返回"服务暂时不可用，请稍后重试"，保留会话 |
| C-E4 流式中断 | 流式响应中途断开 | 保留已返回部分，提示"回复中断，请重试"，不出现半截 Markdown |
| C-E5 接口超时 | 响应超时 | 终止本次请求，提示超时，允许重发 |
| C-E6 无关/违规输入 | 与医疗无关或违规内容 | 引导回归健康咨询主题，不做无关回答 |
| C-E7 急危重症输入 | 胸痛/呼吸困难/大出血/意识丧失等 | 优先返回"立即拨打急救电话或就近就医" |
| C-E8 重复提交 | 上次请求未完成再次发送 | 禁用发送按钮，阻止重复请求 |
| C-E9 清空误操作 | 用户点击清空 | 二次确认，避免误删对话 |

### 3.4 验收标准

1. 输入"牙疼怎么办"，回答流式展示、Markdown 排版正确（标题/加粗/列表可见），且完整包含五段式结构，缺任一段判定不通过。
2. 连续追问第二问，AI 回答能正确引用本会话先前内容；清空对话后重新提问，AI 不再携带旧上下文。
3. 空内容/纯空格发送被拒绝且输入框获得焦点；输入超 2000 字符被限制并提示；Enter 发送、Shift+Enter 换行行为正确。
4. AI 回复期间发送按钮禁用；回复完成后恢复可用。
5. 输入"突然胸痛呼吸困难"，回复首要且醒目内容为"立即拨打 120/就近就医"提示。
6. 页面底部固定展示"智能问诊系统 v1.0 | 仅供健康咨询使用，不替代专业医疗建议"；每次回复末尾附免责与就医提示。
7. 模拟接口失败/超时/流式中断，界面给出对应友好提示、会话不丢失、可重试，且无半截 Markdown 残留。

## 4. 模块二：体检报告上传与分析（FR-3～FR-7、FR-13）

### 4.1 详细描述

**报告上传**
- 上传区展示引导文案与**"选择文件"按钮**；支持**点击上传区/按钮**和**拖拽文件**两种方式；拖拽悬停时上传区高亮。
- 一次仅上传一个报告文件；未选择文件不触发分析（提示"请先选择要上传的文件"）。
- 三重校验（前端即时 + 后端兜底，文案一致）：

| 校验项 | 规则 | 不通过提示 |
|--------|------|------------|
| 类型 | 仅 PDF（扩展名 + MIME 双重判断） | "仅支持 PDF 格式" |
| 大小 | ≤10MB | "文件大小不能超过 10MB" |
| 空文件 | 0 字节/空内容拦截 | "文件无效，请重新选择" |

- 上传成功展示文件名（含大小），自动进入解析流程。

**AI 解析**
- 处理链路：上传 → 校验 → PDF 文本提取 → 内容有效性检查 → 组装提示词 → 调用 DeepSeek → 生成结构化结果。
- 解析期间展示加载态：**"AI 正在分析体检报告，请稍候…"**；禁用上传/分析操作防并发。
- 提取文本为空或过短（<50 字）、扫描件、格式异常时提示："报告内容无法识别，请上传清晰 PDF"，允许重试（OCR 为二期扩展）。
- 超时机制：从上传完成到结果展示 ≤120s，超时按解析失败处理。

**分析结果（四段式，缺一不可）**

| 部分 | 内容要求 |
|------|----------|
| 基本信息 | 报告日期、体检机构、姓名、性别、年龄等 |
| 异常项明细 | 逐条列出异常指标：检测值、参考范围、异常状态（⚠️ 偏高/偏低）、针对该指标的改进方案；不得只给结论 |
| 总体健康建议 | 汇总性建议，给出整体健康改善方向 |
| 注意事项 | 需特别留意的风险项与就医提醒 |

- 展示形式：表格/卡片，偏高/偏低用 ⚠️ 标记与颜色区分，非纯文本段落。
- **急危指标提醒**：检出严重异常（如肿瘤标志物显著升高）时，醒目提示"建议尽快就医"，且完整分析不缺失。

**结果操作**
- **下载报告**：导出分析结果供用户保存（导出格式在开发文档定义）；失败提示可重试。
- **重新分析**：清空当前结果，回到上传初始状态，支持更换报告再次完整走流程。

### 4.2 业务规则

| 编号 | 规则 | 说明 |
|---|---|---|
| R-BR-01 | 文件类型校验 | 仅允许 PDF，其他格式拒绝并提示 |
| R-BR-02 | 文件大小校验 | >10MB 拒绝并提示，避免请求超时 |
| R-BR-03 | 空文件校验 | 0 字节文件拦截，提示"文件无效" |
| R-BR-04 | 解析状态管理 | 解析中展示加载态并禁用重复操作 |
| R-BR-05 | 结果结构化 | 结果须含四部分（基本信息/异常明细/总体建议/注意事项） |
| R-BR-06 | 异常项准确性 | 异常项须含检测值、参考范围、异常状态，不得只给结论 |
| R-BR-07 | 解析失败降级 | 失败返回友好提示，允许重新上传或重试 |
| R-BR-08 | 免责强制 | 结果附免责声明，强调不替代专业医疗建议 |
| R-BR-09 | 隐私保护 | 报告内容仅用于本次分析，不落盘或明确告知存储策略 |
| R-BR-10 | 急危指标提醒 | 严重异常指标醒目提示及时就医 |

### 4.3 异常场景

| 场景 | 触发条件 | 预期处理 |
|---|---|---|
| R-E1 非 PDF 文件 | 上传 Word/图片等 | 拒绝，提示"仅支持 PDF 格式" |
| R-E2 文件超限 | >10MB | 拒绝，提示"文件大小不能超过 10MB" |
| R-E3 空文件 | 0 字节 | 拦截，提示"文件无效，请重新选择" |
| R-E4 解析失败 | AI 接口异常/超时/服务错误 | 返回"报告解析失败，请重试"，允许重新上传 |
| R-E5 报告无法识别 | 扫描件模糊/无文本/格式异常 | 提示"报告内容无法识别，请上传清晰 PDF"，允许重试 |
| R-E6 解析中断 | 解析过程网络中断 | 终止本次解析，提示重试，不残留半成品结果 |
| R-E7 重复提交 | 解析中再次上传/点击分析 | 禁用按钮，阻止并发请求 |
| R-E8 下载失败 | 导出时网络异常 | 提示下载失败，允许重试 |
| R-E9 严重异常指标 | 检出急危异常项 | 醒目提示"建议尽快就医"，保留完整分析 |

### 4.4 验收标准

1. 点击"选择文件"可唤起文件选择框（默认过滤 PDF）；拖拽 PDF 上传区有高亮反馈；两种途径上传成功效果一致，均显示文件名并自动进入解析。
2. 非 PDF（jpg/docx/xlsx）、>10MB、0 字节文件分别被拦截，提示文案与上表完全一致；恰好 10MB 允许上传（边界值）；绕过前端直传后端时后端返回相同错误。
3. 解析期间展示"AI 正在分析体检报告，请稍候…"，上传/分析按钮禁用；解析中重复触发操作被阻止；上传完成到结果展示 ≤120s。
4. 合法报告结果完整含四段式结构；每条异常项含检测值、参考范围、⚠️ 状态、改进方案四要素；偏高/偏低颜色区分；仅给结论缺要素判定不通过。
5. 结果页展示"仅供参考，不替代专业医疗建议"；页脚固定免责声明在任意滚动位置可见。
6. 上传无文本层扫描件提示"报告内容无法识别，请上传清晰 PDF"；模拟 AI 异常/超时提示"报告解析失败，请重试"且可重新上传；中断网络不产生半成品结果与脏历史记录。
7. "下载报告"成功导出含完整四段式结果与免责声明的文件，失败可重试；"重新分析"清空当前结果并可完整再次走流程，上一份数据不残留。
8. 含严重异常指标的样例报告触发醒目"建议尽快就医"提示，同时四段式结果完整。
9. 报告原始文件默认分析完成后不落盘留存；如需留存，界面明确告知存储策略。

## 5. 模块三：历史记录（FR-8、FR-9、FR-14）

### 5.1 详细描述

- **咨询历史**：按会话列表展示（标题取首个问题摘要 + 时间，倒序），点击查看完整对话内容。
- **分析历史**：列表展示文件名、分析时间、总体评估摘要，点击查看完整四段式分析报告。
- **删除记录**：每条历史有删除入口，点击后二次确认，确认后不可恢复；取消则无变化。
- 历史数据归属**登录用户**（V1.1 变化：由浏览器标识 client_id 升级为 user_id），仅本人可见。
- 隐私约束（联动 R-BR-09）：历史记录仅存结构化分析结果与会话文本，默认不留存原始 PDF。

### 5.2 验收标准

1. 完成一次咨询/一次报告分析后，历史列表自动出现对应新条目，字段完整（标题/文件名、时间、摘要）。
2. 点击咨询历史条目可完整回看多轮对话；点击分析历史条目可查看完整四段式报告。
3. 删除任一条历史前弹出二次确认；确认后列表移除且不可恢复；取消后数据无变化。
4. 历史记录按时间倒序排列。

## 6. 通用要求（FR-10、FR-11）

### 6.1 合规与免责

- 页面底部固定展示：**"智能问诊系统 v1.0 | 仅供健康咨询使用，不替代专业医疗建议"**。
- 咨询每次 AI 回复末尾、报告分析结果区域均附免责与就医提示。
- 报告/健康数据隐私说明在界面展示。

### 6.2 错误提示总则

- 覆盖全部异常场景（C-E1~E9、R-E1~E9）；文案统一、友好中文，不暴露技术堆栈信息。
- 所有失败场景（请求失败/解析失败/下载失败/超时）必须支持重试或重新操作，系统不崩溃、会话不中断。

## 6.5 模块四：用户认证与登录态历史（FR-15～FR-18，V1.1 新增）

> 详细规则以三份专项需求文档为准：《用户注册功能需求.md》《用户登录功能需求.md》《历史记录查看功能需求.md》。要点摘录：

- **注册（FR-15）**：用户名 3~20 位（字母/数字/下划线）且唯一；密码 6~20 位并二次确认；邮箱标准格式且唯一。异常文案固定："用户名已存在"/"邮箱已被注册"/"密码不一致，请重新输入"/具体格式错误。注册成功跳登录页。密码加盐哈希存储，严禁明文（任何环节不落明文）。
- **登录（FR-16）**：用户名+密码匹配成功 → 进入主页面并维持登录态（服务端会话/Token）；失败**统一提示"用户名或密码错误"**（防用户名枚举）；空值前端拦截。
- **退出（FR-17）**：清除登录态回登录页；登录后历史记录等数据对他人不可见。
- **登录态历史（FR-18）**：未登录访问跳登录页；咨询会话/报告分析双 Tab、时间倒序、点击回看完整内容；删除沿用 FR-14 二次确认；空态"暂无历史记录"。

## 8. 非功能性需求

| 类别 | 要求 |
|------|------|
| 性能 | 咨询流式输出首字 ≤5s；报告分析全程 ≤120s；页面常规操作响应流畅无明显卡顿 |
| 安全 | DeepSeek API Key 仅存后端环境变量，严禁进入前端与代码仓库；上传类型白名单；文件名/路径安全处理防路径穿越；单文件大小限制防资源耗尽；**用户密码加盐哈希存储，登录/注册接口与日志不落明文；登录凭证（Token）校验归属，防越权访问他人历史** |
| 隐私 | 健康数据为敏感个人信息：报告内容仅用于本次分析、默认不落盘原始 PDF；历史仅存结构化结果；页面明示隐私说明 |
| 可用性 | 医学小白可无指导上手；处理全程状态可视（上传→解析→完成/失败）；适配 Chrome/Edge |
| 合规 | 全程"非诊断"定位；急危场景强制就医引导；免责展示无死角（页脚固定 + 内容附注） |
| 可维护性 | 前后端分离、分层清晰；DeepSeek 调用封装为独立模块，可替换模型；AI 输出使用统一结构化 Schema（阶段 3 定义） |
| 容错 | AI 服务限流/异常/超时全部友好降级；重试机制；错误日志后端留存便于排查 |

## 11. 决策记录与待确认事项

**已确认：**
- 大模型采用 DeepSeek；仅普通用户单角色。
- 上传交互：点击/拖拽 + "选择文件"按钮；仅 PDF、≤10MB、空文件拦截。
- 咨询采用流式输出 + Markdown 渲染；AI 回答五段式结构。
- 报告分析结果四段式结构；下载报告、重新分析；急危指标醒目提醒。
- 隐私策略：报告内容仅用于本次分析，默认不落盘原始 PDF。
- **需要用户注册/登录**（V1.1 新增 FR-15～FR-18）：独立登录/注册页（选项卡式），注册成功跳登录，登录成功进主页面；历史记录按登录用户归属。
- 技术栈：后端 Python（FastAPI + uv，SQLite `backend/ai_clinic.db`）；前端静态页面 + 原生 JS；大模型 deepseek-v4-flash。

**待确认：**
- 无。
